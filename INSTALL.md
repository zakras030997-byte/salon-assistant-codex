# Установка плагина Salon Assistant 0.8.2

## Рекомендуемый путь: GitHub → установщик → плагин → рабочий проект

Скачайте этот публичный репозиторий или ZIP в отдельную папку исходников. Пароль GitHub не нужен. В Codex попросите: «Установи плагин Salon Assistant и подготовь отдельный рабочий проект». Агент читает этот файл, проверяет Python 3.10+ и официальный Codex CLI с командами `plugin marketplace add`, `plugin add`, `plugin list`. Если CLI отсутствует, его установка — отдельный видимый шаг по [официальной инструкции](https://learn.chatgpt.com/docs/codex/cli); установщик не скачивает и не исполняет сторонние программы автоматически.

Для новой пустой рабочей папки:

```bash
python3 scripts/install_plugin.py --project <абсолютный-путь-рабочей-папки>
```

Установщик:

1. Подготавливает рабочую папку с `AGENTS.md` и `system/BOOTSTRAP.json`, без копий `.agents/skills`.
2. Собирает постоянный каталог плагина в `~/.local/share/salon-assistant/0.8.2`. Там лежат только исходники, шесть навыков и лицензия.
3. Регистрирует этот локальный каталог `salon-assistant` штатной командой Codex и устанавливает `svetlana-assistant@salon-assistant`.
4. Проверяет через Codex имя, версию, источник и включённое состояние плагина. Сохраняет результат и журнал в `system` рабочей папки.

Откройте созданную рабочую папку в Codex, начните **новую задачу** и напишите «Привет». Установленный плагин запускает мастер персонализации. Установка сама не начинает диалог. В каталоге плагинов помощник отображается как **Salon Assistant**. Это локально установленный плагин из открытых исходников; публикация в общем каталоге OpenAI — отдельная процедура.

Google Drive/Sheets и Google Calendar подключаются через их плагины. Светлана подтверждает доступ в браузере сама. Установщик не переносит аккаунт разработчика, не запрашивает пароль в чате и не создаёт Google-ресурсы. Мастер проверит свой аккаунт, корень, клиентскую базу, календарь и склад после подключения. Успешная установка плагина не означает готовность Google и клиентскую приёмку.

## Облачный проект ChatGPT/Codex

В постоянном облачном проекте плагин работает без локальной рабочей папки и без `system/BOOTSTRAP.json`. После проверки Google-аккаунта и точного корня мастер создаёт или обновляет одну `system/CLOUD-PROJECT-CONTEXT.json` в постоянных файлах этого проекта по шаблону `templates/CLOUD-PROJECT-CONTEXT.json`. Она содержит только стабильный ключ проекта и проверенные ID контекста/корня, без OAuth-данных и клиентских сведений. Следующая задача и другое устройство читают эту же привязку. Если указатели противоречат друг другу, не создавайте новый корень и не повторяйте запись: сначала проверьте старую привязку и выберите единственный подтверждённый контекст.

## Повтор и сохранение данных

Повтор локального запуска читает состояние установки и сохраняет `BOOTSTRAP.json` побайтно, включая root/context IDs и ответы. Повтор облачного запуска использует `CLOUD-PROJECT-CONTEXT.json` и не создаёт локальный указатель. Не удаляйте постоянную папку плагина: Codex использует её как источник. `--marketplace-root <путь>` позволяет выбрать другую постоянную папку до первой установки. Она должна быть отдельно от исходников и рабочего проекта.

При неизвестном исходе добавления каталога или плагина установщик сначала проверяет состояние через Codex; незавершённое намерение не повторяется вслепую. Если данные/версия/источник не совпадают или каталог уже связан с другим пакетом, он остановится с пояснением. Уже установленный, но выключенный плагин не включается молча.

Автоматическое обновление уже зарегистрированного plugin-mode из прежнего каталога пока не входит в пакет: если `salon-assistant` связан с источником старой версии, установщик остановится, ничего не удаляя. Сначала отдельно проверьте текущий источник и выполните явную переустановку по подтверждённой процедуре; не удаляйте каталог плагина или рабочую папку ради обхода проверки.

Существующий проект с `.agents/skills` из 0.6.2/0.7.0 не переводится автоматически в plugin mode: установщик отклонит смешанную установку, сохранив файлы и Google-привязку. Продолжайте его прежним способом; переход рабочего проекта требует отдельной проверяемой миграции. Не создавайте для него новый Google-корень.

Для проверки сборки без установки в Codex доступен `--prepare-only`. Результат `prepared_only` не означает установленный плагин. Для полной передачи нужны `plugin_installed_verified`, проверка обнаружения навыков в новой задаче и отдельная проверка Google на устройстве владельца.

# Прежний вариант: скиллы внутри отдельного проекта

## Доступ к пакету

Репозиторий публичный: пароль, приглашение и вход GitHub для скачивания не нужны. Агент может получить исходники по ссылке через Git или скачать ZIP в меню Code → Download ZIP. При доступном Git:

```bash
git clone https://github.com/zakras030997-byte/salon-assistant-codex.git
```

После скачивания агент читает инструкции внутри пакета. Получение исходников не выполняет Google-вход и не создаёт рабочие таблицы. Не сохраняй клиентские данные в каталоге клона.

## Установка скиллов без регистрации плагина

1. Получи файлы в отдельную папку исходников, прочитай `AGENTS.md` и этот документ. Проверь Python 3.10+, доступ к локальным файлам и нужную версию пакета.
2. Выбери отдельную новую рабочую папку для Светланы. Выполни `python3 scripts/install_project.py --project <абсолютный-путь>`; на Windows используй доступный Python 3.10+ и корректно заключай путь в кавычки. Сценарий не меняет существующую непустую чужую папку.
3. Проверь вывод установщика и созданные файлы. Открой рабочую папку как локальный проект Codex. Начни новую задачу, чтобы Codex обнаружил `.agents/skills`, и напиши «Привет».
4. Главный навык запускает мастер. Подключи Google Drive и Google Calendar от аккаунта Светланы через доступный каталог плагинов, подтверди доступ в браузере. Если после установки Google-плагина инструменты ещё не появились, начни новую задачу и продолжи с сохранённого места.
5. Мастер проверяет аккаунт, создаёт/привязывает корень, папки, нативные таблицы и календарь; сохраняет ответы в `system` на Google Drive. После проверки анкеты и схемы выполняет согласованный тест записи/чтения и очистки.

Установщик подключает скиллы к конкретному проекту через `.agents/skills`; он не регистрирует глобальный плагин в каталоге Codex и не меняет глобальные настройки. В пакете также есть `.codex-plugin/plugin.json` для дальнейшей упаковки в локальный marketplace. Для сценария «ссылка → установи → новая задача → Привет» достаточно установленного рабочего проекта. Не обещай автоматическую авторизацию Google, создание календаря при отсутствии такого инструмента или работу без доступа к сети.

## Сохранение состояния

Повтор той же установки сохраняет `system/BOOTSTRAP.json`, рабочие каталоги и файлы пользователя. Без флага обновления несовпадение версии останавливает установку. При утрате `BOOTSTRAP.json` установщик останавливается: сначала восстанови указатель на существующий облачный корень и контекст, не создавай второй проект. Не клонируй рабочие данные обратно в репозиторий.

Для согласованного обновления legacy-проекта **0.6.2, 0.7.0, 0.8.0 или 0.8.1 → 0.8.2** выполни `python3 scripts/install_project.py --project <абсолютный-путь-существующего-проекта> --upgrade`. Установщик сначала проверяет старые принадлежащие пакету файлы, сохраняет BOOTSTRAP и посторонние рабочие файлы, обновляет ядро и добавляет шестой навык. При ручных изменениях остановится до перезаписи; сначала разберите конкретные отличия. Прерванное обновление продолжается той же командой по журналу `system/UPGRADE.json`; не удаляй журнал для обхода проверки.

После обновления открой новую задачу рабочего проекта и напиши «Обнови базу». Навык читает прежний облачный контекст и использует клиентскую базу, карточки и оперативку в том же корне. Уже существующие таблицы и профиль сохраняются. Таблица лидов не создаётся и не требуется; если она осталась от старой версии, её данные не меняются. Копирование исходников само по себе не означает завершения этого облачного шага; доступ Google нужен отдельно.

Перед публикацией изменений проверь состав коммита: только исходники пакета. Публикация рабочей папки пользователя не входит в обновление кода. Полные клиентские таблицы, фотографии, заполненный контекст, реальные Google-ID и секреты в пакет не входят.

## Приёмка на компьютере Светланы

- Новый проект и новое «Привет» действительно открывают мастер; перезапуск продолжает сохранённый вопрос.
- Все ресурсы созданы/привязаны в её аккаунте, MIME и родитель каждой таблицы проверены.
- «Клиентская база» существует до образца, а импорт сохраняет её ID.
- Пример базы читается из файла или скриншота; размытые заголовки не выдумываются.
- Один вымышленный сеанс читается и в таблице, и в календаре; повтор не создаёт второй сеанс.
- Приход материала по фото/накладной проверен с единицами и историей; фото полупустого флакона без измерения оставляет остаток неизвестным.
- Потерянный ответ не вызывает повторную запись; частичный результат честно отображается.
- Обновление исходников не стирает профиль и данные.
- После первого мастера «Обнови базу» выбирает клиентскую базу, карточку и оперативку по подтверждённым фактам; адреса берутся из её контекста.
- Повтор команды не меняет строки, даты и версии без новых сведений; результат старого сеанса не заменяет активный.
- Обновление legacy-проекта с 0.6.2, 0.7.0 или 0.8.0 сохраняет корень, аккаунт, deployment_id, context_file_id и пользовательские файлы; прерывание возобновляется без сброса привязки.
