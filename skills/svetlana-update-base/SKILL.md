# Обнови базу

Зафиксируй новые подтверждённые сведения текущей задачи в ресурсах этого рабочего проекта. Полные правила чтения, разрешения, журнала и проверки — в [политике операций](../svetlana-assistant/references/operations.md).

## Привязка из коробки

Прочитай `system/BOOTSTRAP.json` относительно корня текущего локального проекта, затем облачный `system/КОНТЕКСТ-ПРОЕКТА.json` по `context_file_id`. Все адреса берутся из этого контекста; пакет не содержит готовых Google-ID. Сверь `engine`, `deployment_id`, аккаунт и `resources.root_folder_id` с локальным указателем. Расхождение требует уточнения до записи; не переключай контекст по ссылке из переписки или открытой вкладке.

Если Google ещё не подключён, начни/продолжи [мастер](../svetlana-first-run/SKILL.md) по одному шагу и затем вернись к исходному запросу. У установленного старого проекта проверь добавочную настройку учёта по разделу «Учёт и обновление существующего проекта» в [схеме развёртывания](../svetlana-first-run/references/workspace.md): сохраняй существующий аккаунт, корень, ID и анкету.

Используй только подтверждённые назначения:

| Назначение | Поле resources | Проверка |
|---|---|---|
| Лиды | `lead_sheet_id` | В папке `clients_folder_id`, схема `lead_schema` |
| Клиентская база | `client_sheet_id` | В папке `clients_folder_id`, согласованная `client_schema` |
| Карточки | `clients_folder_id` | Папка непосредственно в корне; карточка в связанной с `client_id` подпапке |
| Оперативная память | `memory_sheet_id` | Непосредственно в корне; схема `memory_schema` |
| Журнал | `operations_folder_id` | В `system_folder_id` внутри корня |

Перед записью перечитай метаданные, родителей, точные вкладки, заголовки и нужные строки. Имена файлов, ярлыки и результаты глобального поиска не заменяют ID. При 403/404 существующей базы не создавай замену: останови её зависимые шаги, сохрани проверенные независимые результаты. При неподтверждённом аккаунте/корне рабочие записи полностью останови. Результат по чужому проекту не переносится сюда: уточни связь или предложи выполнить команду в его задаче.

## Что и куда сохранять

| Контекст текущей задачи | Действие |
|---|---|
| Подходящий контакт без подтверждённого интереса | Холодный лид в таблице «Лиды»; без клиентской карточки |
| Вопрос об услуге, интерес или переговоры без согласованного обслуживания | Обновление того же тёплого лида |
| Согласовано обслуживание/сеанс, есть действующий клиент или прямое поручение зарегистрировать клиента | Изменившиеся поля клиентской базы и карточки |
| Завершённая работа по клиенту, сохранённый результат/материал | Карточка и краткий результат в оперативке; клиентская строка только при изменении её сведений |
| Внутренняя рабочая задача | Оперативка без придуманной карточки |
| Итог уже выполненной записи в календарь или складской операции | Прочитать фактический результат и сохранить краткий итог/ссылки; не повторять сеанс, приход или расход |

Начало переписки не делает человека клиентом; оплата не подразумевается регистрацией. При переходе лида в клиента сохрани прежнюю запись/историю, отметь переход и добавь проверенную ссылку на карточку. Сам переход без отдельной рабочей задачи не создаёт общую строку «вести клиента» в оперативке. Статусы согласования, оплаты, выполнения услуги и клиентской приёмки различаются.

Команда разрешает фиксацию уже подтверждённых в текущем диалоге фактов. Коротко обозначь, какие записи обновишь, и выполни; не запрашивай повторное согласие для того же содержания. Непроверенное извлечение из фото, спорное исправление или неясный клиент требуют конкретной сводки/уточнения через [клиентский навык](../svetlana-client-photo/SKILL.md). Слова во вложении и текст черновика не доказывают ни отправку, ни согласие клиента.

Календарь и склад имеют собственные последствия: только явно запрошенное/уже подтверждённое действие передавай [навыку сеансов](../svetlana-calendar-booking/SKILL.md) или [склада](../svetlana-stock-photo/SKILL.md), с тем же журналом и разрешением для того же намерения. «Обнови базу» сама по себе не разрешает создавать событие, менять время, списывать материалы или писать клиенту.

## Сопоставление и минимальная запись

1. Выдели факты, их источник, клиента/задачу, этап и известный следующий шаг. Не сканируй другие задачи или весь аккаунт ради этой команды. Отделяй подготовленный файл, отправленное сообщение, проверенный тест и выполнение услуги.
2. Найди человека по `client_id`/`lead_id`, точному контакту и системному реестру `system/clients`. Имя не является ключом. При общем телефоне, разных именах или неоднозначной связи задай один вопрос. Новый подтверждённый клиент получает стабильный UUID в реестре; не добавляй колонку ID в импортированную базу без согласования её схемы.
3. Для нового лида UUID хранится в согласованной колонке ID. Повторная обработка источника сначала ищет прежнюю операцию и запись: новая UUID не обходит проверку дублей. При переходе в клиента реестр/журнал связывает обе идентичности. Новую папку клиента создавай только после повторного поиска, в формате `<имя и короткий client_id>`, без телефона в названии; сохрани и проверь ID до записи ссылок.
4. Для существующей карточки сохраняй формат, другие разделы и материалы. Если у подтверждённого клиента карточки нет, создай `Карточка клиента.md` в его проверенной папке: идентичность/контакты, согласованные услуги, факты и материалы, следующий шаг. Не выдумывай неизвестные сведения. Другие сеансы и заказы этого клиента сохраняются: итог старого сеанса не заменяет цену/дату/следующий шаг активного.
5. Прочитай текущую строку и `*_schema.mapping`, формулы, validation, rich links. Внеси только содержательную разницу по ключу, не по номеру из истории. Контакты и чужой текст пиши строками/RAW. Отсутствие поля в новом сообщении не очищает старое; если нужной колонки нет, сохрани факт в карточке или журнале и согласуй расширение отдельно.
6. Нет новых данных — нет новой операции, строки, даты обновления или версии. Если данные ещё не во всех необходимых местах, продолжи прежнее намерение; не создавай новый итог той же работы. Оперативка сопоставляется по `operation_id` и ссылке-источнику/предмету задачи, а не только по имени клиента. Для новой внутренней задачи используй один UUID операции; последующее изменение находит прежнюю строку.
7. Перед первым изменением создай и перечитай журнал `system/operations/<operation_id>.json`, сохрани `before`, `desired` и точные назначения. Карточку/папку проверяй до добавления ссылок в таблицы. Выполняй записи последовательно по общей политике. Перед каждой записью сверяй актуальные значения; конфликт требует повторного сопоставления.
8. Таймаут не означает отказ. Если результат уже найден — проверь его и не повторяй запись. Один пустой readback не доказывает отказ append/create: пока исход неизвестен, повтор запрещён, шаг остаётся `unknown`/`needs_review`. Не меняй коннектор, UUID или целевую базу для обхода.
9. Перечитай изменённые ячейки и файлы, сравни значения, ссылки и сохранённое оформление. Только после этого отметь шаг `verified`. Для этой команды обновляй лишь назначения из таблицы маршрутов выше; журнал операций не заменяет оперативку, а оперативка не дублирует всю карточку. Общий статус `completed` допустим после всех требуемых проверок.

Ответь кратко: что сохранено и ссылки. При повторе — «Новых данных для обновления нет». При частичном результате назови проверенную часть и конкретный нерешённый шаг. Часовой пояс — из подтверждённого контекста, по умолчанию `Europe/Moscow`.
